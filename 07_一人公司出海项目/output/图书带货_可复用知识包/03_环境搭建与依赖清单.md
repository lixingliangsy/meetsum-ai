# 环境搭建与依赖清单（含 5 个必踩的坑）

> 本文给你在另一台电脑上把流水线跑起来的最小环境，以及本机实测必踩的 5 个坑。脚本与配置见 04，质检见 05。

## 一、环境清单

| 依赖 | 版本/说明 | 安装 | 验证 |

| Node.js | 22+（managed 或系统） | 安装 Node 22 | `node -v` |

## 二、⚠️ 必踩坑 ①：FFmpeg 不在 PATH

本机 `ffmpeg` 不在默认 PATH，`which ffmpeg` 返回空；managed python 3.13 有 encodings 故障。**实测可用路径**：`C:\tools\ffmpeg.exe`（以及 `ffprobe.exe` 同目录）。
**解决**：要么把 `C:\tools` 加进 PATH，要么在脚本/命令里写全路径；ffprobe 同理（`C:\Users\lixingliang\AppData\Local\Microsoft\WinGet\Links\ffprobe.exe` 也是一处可用位置）。

---

## 三、⚠️ 必踩坑 ②：码率被压到 <1MB（A 版纯色背景）

**现象**：A 版视频仅 0.79MB，低于 1MB 红线，画质发虚。
**根因**：原渲染器用 `-c:v libx264 -crf 20 -preset medium`。CRF 模式下，极简静态背景会被编码器自动判为"无变化"而压到 **103kbps**，文件极小、码率不达标。
**解决**：改为目标码率约束（已写入 04 的 `render_topic.py`）：
```
-c:v libx264 -b:v 1000k -maxrate 1500k -bufsize 3000k -preset medium
```
改后 A 版恢复到 1.06–1.11MB（~171kbps），B 版 3.99–4.19MB（~608kbps），全部达标。

---

## 四、⚠️ 必踩坑 ③：ASS 字幕分辨率错乱（字号/边距爆掉）

**现象**：字幕被放大、位置错乱、压到小黄车。
**根因**：手搓 ASS 未显式声明分辨率，libass 默认按 **384×288** 放大到 1080×1920，比例全错。
**解决**：ASS 头部必须显式写：
```
[Script Info]
WrapStyle=2
PlayResX: 1080
PlayResY: 1920
```
中文长句用 `wrap_cn()` 按字数硬折行（ASS 中文无空格不自动换行）。04 的渲染器已内建，勿改。

---

## 五、⚠️ 必踩坑 ④：ffprobe 返回的 "1080,1920" 不是 "1080x1920"

**现象**：质检脚本报 `分辨率 1080x1920 不符` 的假 ⚠️。
**根因**：`ffprobe -show_entries stream=width,height` 返回逗号分隔 `1080,1920`，脚本若按 `1080x1920`（x）比对会永远不匹配。
**解决**：比对时 `replace(',', 'x')` 或分别读 `width`/`height` 字段（见 05 质检脚本）。

---

## 六、⚠️ 必踩坑 ⑤：ImageGen 并行同名覆盖 + 任务限流

**现象**：6 张背景图并行生成，结果只剩 1 张；或中途报 "150 任务上限"。
**根因**：并行调用时 output 同名、同时间戳，互相覆盖；后端有并发上限。
**解决**：
- **串行 + 子目录**：每张图进独立 `g1/`~`g6/` 子目录，逐张生成、及时重命名。
- **限流恢复**：触发后停发养号 7–14 天，或错峰重试；同一批不要 >10 张并行。

## 七、配音拼接约定（边缘细节）

- edge-tts 输出 24kHz，静音用 `anullsrc=r=44100`，**统一 `-ar 44100` 后再 concat**，避免采样率不一致。
- 最终 mux 加 `tpad=stop_mode=clone:stop_duration=10` 防 `-shortest` 裁掉尾部配音。
- 亮度/暗角：`eq=brightness=0.15:contrast=1.06` + `drawbox black@0.10`（轻遮罩，别用旧的 0.35 整帧黑遮罩，会整体偏暗）。
- **关键**：ffmpeg `eq=brightness` 是 `-1.0..1.0` 加法偏移（`0`=无变化），轻微提亮写 `0.10–0.20`，**绝对不要写 `1.10`**（那会趋向全白）。
